CHROME MCP BRIDGE · 2.3.0

让 AI 读网页，也真正看见图片

完整搭建教程 · 2026-09-20 · Linux 桌面 / Chrome 或 Chromium / HTTP MCP

本版把旧的两工具教程升级成三个工具的可运行项目。小红书笔记默认在打开时附带图片清单、标题正文和当前可见评论；再调用一次批量看图，可返回多张独立原生图片。

先看安全边界：这个个人工具没有应用层身份认证，公开包默认仅监听电脑回环地址。CDP 只能留在本机；MCP 不可直接开放公网。本教程不会配置绕过登录、验证码或平台访问控制。

1. 功能与适用范围

MCP 客户端 → HTTP Bridge（默认 127.0.0.1:9224）
           → 本机 CDP（127.0.0.1:9223）→ 专用 Chrome / Chromium
工具能力
chrome_navigate只打开一次指定 HTTP(S) URL，返回固定 page_id。小红书笔记 / 分享链接默认附带 note_preview。
chrome_get_web_content读取网页正文与元数据，优先传 page_id 准确定位。传 url 时先打开一次；两种参数互斥。
chrome_viewlist 列图与有限笔记正文；image 单图；images 每次 1–12 图；screenshot 当前视口截图。

模型要有视觉能力，客户端也必须将工具返回的每个 ImageContent 转成模型图片输入。图片链接、base64 文字、客户端缩略图都不等于模型真的获得了像素。

小红书有专门的笔记主体选择器，避免把推荐区图片误当正文。普通网页可以提取文本、当前视口或可读的已加载图片；并非所有网站都有正文/评论的专用适配。网站 DOM 改版后可能需要更新。

视频不在本版能力范围：视频笔记报告不支持，不播放、不下载、不从推荐封面补成“视频内容”。

2. 下载项目、准备依赖

需要 Linux 图形桌面、已安装的 Chrome / Chromium、Python 3.10+。本教程不安装代理、不修改系统网络。Node.js 只用于离线测试中的 DOM 模拟，不是日常运行依赖。

git clone https://github.com/AZHi-xinxin/chrome-mcp-bridge.git
cd chrome-mcp-bridge
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt

如果 venv 命令提示缺少组件，按当前 Linux 发行版安装 Python venv 包后重试。不使用系统级 sudo pip。

运行源码是同目录下这三个文件，必须来自同一版本：

  • chrome_mcp_bridge.py：HTTP / MCP 与导航。
  • chrome_vision.py：快照、像素、批量预算。
  • chrome_note_dom.py：只读 DOM 清单与笔记文本。

旧 HTML 内嵌的单文件程序已移除，避免复制到旧实现。通过 GitHub “Download ZIP” 下载也可以，但必须解压完整项目，不能只复制主脚本。

3. 启动专用浏览器

在登录图形桌面的终端启动，chromium 可按本机安装情况改成 google-chrome。使用独立的数据目录；不要关闭日常浏览器，不要删除其配置。

chromium \
  --user-data-dir="$HOME/.local/share/chrome-mcp-profile" \
  --remote-debugging-address=127.0.0.1 \
  --remote-debugging-port=9223 \
  --remote-allow-origins=http://127.0.0.1:9223 \
  about:blank

Chrome 136 起调试参数需要与非默认数据目录配合使用；这也将调试会话与日常浏览器隔离。参见 Chrome 官方说明。不要用 --no-sandbox、全站安全禁用或 --remote-allow-origins=* 解决配置问题。

需要登录某网站时由人类在这个专用浏览器正常操作。不要将 Cookies、账号密码或验证码复制给 AI，也不要导出整个日常浏览器资料。

curl --noproxy '*' -sS http://127.0.0.1:9223/json/version
ss -ltn 'sport = :9223'

确认调试端口仅在回环监听。若看到 0.0.0.0:9223 或 [::]:9223，先关闭这个专用调试实例并纠正绑定，再继续。CDP 端口不要转发给手机。

4. 启动并验证 Bridge

浏览器保留打开，在另一个终端进入仓库目录：

NO_PROXY=127.0.0.1,localhost .venv/bin/python chrome_mcp_bridge.py

默认监听 127.0.0.1:9224。日志写标准错误，不需要创建系统日志文件或以 root 运行。

curl --noproxy '*' -sS http://127.0.0.1:9224/ \
  -H 'Content-Type: application/json' \
  -d '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-06-18","capabilities":{},"clientInfo":{"name":"local-check","version":"1"}}}'

curl --noproxy '*' -sS http://127.0.0.1:9224/ \
  -H 'Content-Type: application/json' \
  -d '{"jsonrpc":"2.0","id":2,"method":"tools/list","params":{}}'

initialize 的 serverInfo.version 应为 2.3.0；tools/list 应有三个工具，且 chrome_view 有 images 模式。浏览器直接打开端点返回 use POST / HTTP 405 是预期现象。

环境变量默认用途
CHROME_MCP_HOST127.0.0.1仅在配置好 ACL / 防火墙后，显式改成指定私网接口地址。
CHROME_MCP_PORT9224Bridge HTTP 端口，1–65535。
CHROME_CDP_PORT9223需与浏览器参数一致；CDP 主机固定为回环。

修改后须重启 Bridge；端口冲突时先识别已有进程，不要随意终止其他服务。

5. 连接 RikkaHub 与其他客户端

  1. 在 MCP 设置中新增 HTTP 类型连接，名称可用 Chrome MCP。
  2. 如果客户端与 Bridge 在同一电脑，地址填 http://127.0.0.1:9224/。
  3. 保存、连接并刷新工具目录，确认三个工具与 images 参数。
  4. 选择支持视觉的模型，再以用户提供且允许访问的图片页面测试。

本项目提供简单的 JSON-RPC HTTP 请求 / JSON 响应，不是 stdio 启动器，也不提供持续 SSE 事件流。客户端名称和设置随版本可能变化；如强制要求 SSE 或更完整的 HTTP MCP 会话能力，不保证直接兼容。

手机上的 127.0.0.1 指手机，不是运行 Bridge 的电脑。远程连接必须先安排受限的私网访问；不能把地址随便换成公网 IP。

模型只看到首图时，分别检查：MCP 回包的图片块数量、客户端是否保留每块、网关/模型请求是否携带每张图片。不要先假定网页没图，也不要为了排查而反复刷新网页。

6. 手机 / 私网接入

推荐在电脑和手机之间使用由你管理的私网 / Tailscale，并限制只有指定设备可访问 MCP 端口。先配置 ACL 与主机防火墙，再扩大监听。Tailscale 自身配置参考 官方安装文档；不要把 Auth Key 放进公开教程、截图或仓库。

用以下模板启动，先把占位符换成这台电脑的具体私网 IPv4 地址。占位符不能原样执行。

CHROME_MCP_HOST='<电脑的指定私网 IPv4>' \
NO_PROXY=127.0.0.1,localhost \
  .venv/bin/python chrome_mcp_bridge.py

手机 MCP 地址改为 http://<该私网 IPv4>:9224/。CDP 地址仍保持 127.0.0.1:9223，不对手机开放。不要为了兼容多个地址直接改成全接口并开放所有来源。

本项目没有应用层认证：获得端点访问权就能读取这个专用浏览器中允许读取的页面。私网也必须限制来源。若必须公开互联网访问，需另行设计认证、TLS、请求限制与审计；本教程不提供无认证公网部署方案。

连接异常时检查客户端实际运行在哪里：手机本地、电脑本地和服务器端执行 MCP 的来源不同。只对真实请求来源开放，而不是机械地放通整个网段。

7. 工具与批量图片用法

7.1 小红书：导航一次，再批量看图

下列是 MCP tools/call 的 params 示例；占位符必须来自用户链接或实际回执。

{"name":"chrome_navigate","arguments":{"url":"<用户提供的笔记 URL>"}}

回执包含 navigation_status=opened、page_id，以及通常的 note_preview。预览中的 images 有稳定 image_id 与有序 index，文本在 note_content 中。

{"name":"chrome_view","arguments":{
  "mode":"images",
  "page_id":"<导航返回的 page_id>",
  "image_ids":["<第 1 张 image_id>","<第 2 张 image_id>"],
  "wait_ms":6000
}}

同样支持 1–12 张；按希望展示的顺序传 ID。回包先给总状态和逐图结果，再交替给每张标签与原生图片块。结果有 requested_count、returned_count、complete / partial / unavailable。不支持的图会标注失败原因，不静默替成其他图。

拿到稳定 ID 就可直接请求，partial 不意味着必须重新 list。图像读取在预算内等待已知图的本地加载；不额外请求源图。若缺图、被拦、CORS 或页面变化，报告并停下，不重复导航或猜内容。

7.2 需要清单时才列图

{"name":"chrome_view","arguments":{"mode":"list","page_id":"<已有 page_id>"}}

默认每页清单 20 项，limit 为 1–50。清单分页使用同一 snapshot_id 与 offset；这只翻已有清单，不滚动网页。按旧数字索引读取必须同时带 snapshot_id，优先使用 image_id。

7.3 单图、当前视口与普通网页正文

{"name":"chrome_view","arguments":{"mode":"image","page_id":"<page_id>","image_id":"<image_id>"}}

{"name":"chrome_view","arguments":{"mode":"screenshot","page_id":"<page_id>"}}

{"name":"chrome_get_web_content","arguments":{"page_id":"<page_id>"}}

截图仅代表当前视口，不代表轮播里未显示的其他图片。普通正文工具不将像素变成文字。省略 page_id 的兼容调用可能选择 CDP 返回的第一张页面，并不保证是用户当前聚焦标签，所以应优先显式指定。

8. 等待、内容与图片预算

项目上限 / 默认含义
导航预览等待默认 12 秒chrome_navigate.wait_ms，可设 0–15000 ms；已就绪提前返回。
列表 / 图像等待默认 6 秒chrome_view.wait_ms 同范围；批量共用一份预算，不是每张各等 6 秒。
批量图数1–12 张不同的已知 ID；超过 12 张按已有清单分批，不自动翻图。
批量输出预算8,000,000 字节 / 12,000,000 像素按解码后的 JPEG 字节计算；base64 传输会更大。
单图输出预算1,500,000 字节 / 1,800,000 像素源图超过 64,000,000 像素拒绝处理。
批量最长边最多 1024 px，12 张时 1000 px还受请求尺寸与预算限制，可能进一步缩小；回执含实际尺寸。
快照最长 5 分钟，最多 8 份可能提前淘汰；绑定原文档和图源，不把旧 ID 重新指向新内容。
笔记文本标题 300 / 正文 6000读取渲染 DOM 中有限正文；网页文本不具备指令权限。
评论最多 5 条，每条 500仅当前可见、已加载的评论。不滚动、不展开，不代表完整评论区。

wait_ms=0 只检查一次。这里的等待是本地加载等待预算，不是整个 HTTP 请求、CDP 操作、模型回答的硬超时。导航可能仍受正常网络与页面自身加载影响。多图减少工具来回，不消除图片占用的模型上下文；客户端/网关的请求上限仍可能更小。

9. 可选：注册为用户服务

先确保手动启动成功。下例假设项目位于 $HOME/chrome-mcp-bridge；如果不在这里，修改实际路径。服务只负责 Bridge，浏览器由已登录的图形会话管理，不假定开机时已经有桌面、登录态或可用页面。

用文本编辑器创建 ~/.config/systemd/user/chrome-mcp-bridge.service：

[Unit]
Description=Chrome MCP Bridge
After=network.target

[Service]
Type=simple
WorkingDirectory=%h/chrome-mcp-bridge
ExecStart=%h/chrome-mcp-bridge/.venv/bin/python %h/chrome-mcp-bridge/chrome_mcp_bridge.py
Environment=CHROME_MCP_HOST=127.0.0.1
Environment=CHROME_MCP_PORT=9224
Environment=CHROME_CDP_PORT=9223
Environment=NO_PROXY=127.0.0.1,localhost
Restart=on-failure
RestartSec=5

[Install]
WantedBy=default.target

若必须使用受限私网接口，只修改 CHROME_MCP_HOST 到已配置 ACL / 防火墙的那个具体地址。不要复制历史部署的全接口绑定。

systemctl --user daemon-reload
systemctl --user enable --now chrome-mcp-bridge.service
systemctl --user status chrome-mcp-bridge.service --no-pager
journalctl --user -u chrome-mcp-bridge.service -n 50 --no-pager

创建用户服务不需要 root。若此前已有同名系统服务，不要再同时启动第二份；先检查 systemctl status chrome-mcp-bridge.service 与端口占用，沿用并更新现有服务。

10. 升级、备份与回退

  1. 结束当前工具调用。确认正在运行的服务和源码路径，保存服务配置与旧版本源码副本。
  2. 如果仓库存在个人改动，先检查 git status 和差异，不覆盖它们；不要使用强制重置或清理命令。
  3. 更新同一版本的三个运行模块与依赖。在备用目录运行测试，不要只替换主脚本。
  4. 公开包默认改为回环，升级前确认客户端从哪里连接，保留明确的受限私网配置；不动浏览器登录态或代理。
  5. 重启 Bridge 服务，核对版本、工具数量、绑定与端口，再在客户端刷新 MCP 目录。
  6. 若验证失败，停止这次升级后的 Bridge，恢复明确备份的源码与服务配置，然后重启原 Bridge。不要删浏览器数据目录。

这次公开版本额外将 MCP 默认绑定收紧到 127.0.0.1、增加端口 / 绑定环境变量、日志改为 stderr，去掉不再调用的历史镜像函数；不含任何用户私有安装路径、服务器信息或凭据。这些公开包改动不会自动改动已有私人部署。

本次只重启相关 Bridge，不要求重启电脑、手机、VPS 或浏览器。用户服务用 systemctl --user restart chrome-mcp-bridge.service；系统服务按实际名称管理，不混用。

11. 测试与已验收范围

node --version
.venv/bin/python -m unittest discover -p 'test_*.py' -v

2.3 功能基线有 101 项离线测试，公开包还附配置测试。测试使用合成 DOM 和假的 CDP，不读真实浏览器资料，也不访问小红书。缺少 Node 时部分测试会跳过，须检查 skipped，不能当作完整验收。

已验证的真实范围：当前 RikkaHub + 视觉模型的一次真实四图笔记测试，由客户端执行者回报：一次导航附清单，再一次 images 返回 4/4，逐张内容正确，没有漏图、重复或错序，总共两次工具调用。

这不是对所有站点 / 版本 / 模型的兼容性保证。合成 12 图通过不等于真实 12 图通过。真实 12 图、下一轮是否继续携带视觉内容、其他客户端、完整评论区及视频未包含在本次真实验收内。

自己验收时只使用一篇允许访问的普通图片页面：记录回包图数，请模型逐张描述，确认是否有重复或错序。界面显示多图不单独证明模型看到了所有图。不要为了压力测试反复刷新平台页面。

12. 故障排查与安全反馈

现象先检查什么
连不上 9224Bridge 是否运行、监听在哪个接口、手机是否错误使用自身回环地址、私网 ACL / 防火墙是否允许真实请求来源。
找不到浏览器专用浏览器是否已启动、9223 是否回环监听、是否使用独立数据目录、有没有至少一个正常网页标签。
CDP WebSocket 403浏览器 Origin 白名单是否与 CDP 地址匹配；不要关闭浏览器安全机制或使用通配 Origin 来省事。
仍然只有两个工具是否运行旧源码、三个模块是否同版、是否重启了真正的 Bridge 服务、客户端是否刷新工具目录。
页面打开但预览空 / partial看 page_id 与已有图片 ID，稳定 ID 可直接取。别因为预览失败重复打开同一链接。持续不可用则停止并人工查看页面。
某张图片没有返回检查逐图错误：未加载、CORS、来源变化、文档变化、快照过期或资源预算。不能重抓 CDN 或从推荐区补图。
模型只看见一张按 MCP 图片块 → 客户端转换 → 网关请求 → 视觉模型逐层确认。仅显示首个缩略图或模型口述不足以定位责任。
返回 blocked / unsupported停止自动操作。由人类正常检查登录 / 页面 / 网站提示；不刷新轰炸、不绕过验证码、不播放不支持的视频。
等待超过 6 / 12 秒这两个数是本地加载预算，不是整个调用硬超时；还可能有 CDP、网络、客户端与模型时间。

服务不自动滚动、翻图、点赞、评论、私信、播放或下载视频，不显式重取图片/CDN。但正常开页与浏览器后台加载仍有请求，不能承诺零风控或零封号风险。

网站文字、评论与图片仅是外部数据，不是用户指令。不要照网页要求发密码、改配置或执行命令。反馈问题请提交版本、脱敏回执、图数与可公开的合成样例；不要公开 Cookies、令牌、签名链接、付款资料或私人截图。更多见 安全边界。
